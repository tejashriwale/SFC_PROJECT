DIRECT INWARD USES 2 TABLES:
============================

1. MASTER TABLE (One record per farmer/crop collection):
   --------------------------------------------------------
   Possible names:
   • tblCropInvertMaster (older naming)
   • tblCropDirectInvertMaster (newer naming)

   Updated by: SP_AddUpdCropInvertMaster

   Columns (important ones):
   - CROPID (Primary Key)
   - FAID (Farmer ID)
   - CRDATE (Collection Date)
   - CTYPE (Crop Type/Name)
   - CAREA (Crop Area)
   - CONTACTNO (Farmer Contact)
   - NARR (Narration)
   - WEIGHT (Total Weight - sum of all details)
   - AMOUNT (Total Amount - sum of all details)
   - CARET (Total Crates - sum of all details)
   - RATE ← PREVIOUSLY HAD RATE HERE (now removed from usage)

2. DETAIL TABLE (Multiple records per collection - one per row):
   ---------------------------------------------------------------
   Possible names:
   • tblCropInvertDetail (older naming)
   • tblCropDirectInvertDetail (newer naming)

   Updated by: SP_AddUpdCropInvertDetail

   Columns (important ones):
   - CDAID (Primary Key)
   - CROPID (Foreign Key to Master)
   - SHSDATE (Schedule Date)
   - PSIZE (Packing Size)
   - PQUNTITY (Quantity/Crates)
   - WEIGHT (Weight for this row)
   - CGRADE (Grade - A, B, C, etc.)
   - RATE ← NEWLY ADDED - Rate for this detail row
   - VEHNO (Vehicle Number)
   - PACKER (Packer Name)
   - WORKER (Worker Name)

================================================================================
WHAT WAS CHANGED - RATE COLUMN MIGRATION
================================================================================

BEFORE (Rate in Master):
------------------------
Master Table (tblCropInvertMaster):
  CROPID | FAID | CTYPE  | RATE | WEIGHT | AMOUNT
  -----------------------------------------------
  C001   | F001 | Tomato | 50   | 1000   | 50000

Detail Table (tblCropInvertDetail):
  CDAID | CROPID | WEIGHT | GRADE
  --------------------------------
  D001  | C001   | 600    | A
  D002  | C001   | 400    | B

Problem: Both A-grade and B-grade used same rate (50 Rs/kg)


AFTER (Rate in Detail):
-----------------------
Master Table (tblCropInvertMaster):
  CROPID | FAID | CTYPE  | WEIGHT | AMOUNT
  ----------------------------------------
  C001   | F001 | Tomato | 1000   | 42000

Detail Table (tblCropInvertDetail):
  CDAID | CROPID | WEIGHT | GRADE | RATE ← NEW
  --------------------------------------------
  D001  | C001   | 600    | A     | 50   ← A-grade rate
  D002  | C001   | 400    | B     | 30   ← B-grade rate

Calculation:
- D001: 600 kg × 50 Rs = 30,000 Rs
- D002: 400 kg × 30 Rs = 12,000 Rs
- Total Amount: 42,000 Rs ✓

RATE COLUMN DETAILS
================================================================================

Column Specification:
--------------------
Name:     RATE
Type:     DECIMAL(18,2)
Nullable: NULL (can be empty for old records)
Location: Detail Table (tblCropInvertDetail or tblCropDirectInvertDetail)

Usage:
------
- Each detail row has its own Rate value
- Rate is entered per row in the UI
- Amount calculated as: Weight × Rate
- Different grades can have different rates
- Different packing sizes can have different rates

Stored Procedure Parameter:
---------------------------
Parameter Name:  @RATE
Type:           DECIMAL(18,2)
Default:        NULL
SP Name:        SP_AddUpdCropInvertDetail

================================================================================
UPDATE PROCESS
================================================================================

The SQL script (Add_Rate_To_CropInvertDetail.sql) automatically:
----------------------------------------------------------------
1. ✓ Detects which table name you use (tblCropInvertDetail vs tblCropDirectInvertDetail)
2. ✓ Checks if RATE column exists in the detail table
3. ✓ Adds RATE column if it doesn't exist (DECIMAL(18,2) NULL)
4. ✓ Updates SP_AddUpdCropInvertDetail to include @RATE parameter
5. ✓ Adds RATE to INSERT statement
6. ✓ Adds RATE to UPDATE statement
7. ✓ Verifies everything was added correctly

You just need to run it once!

VERIFICATION QUERIES
================================================================================

After running the update script, verify with these queries:

1. Check if RATE column exists in detail table:
------------------------------------------------
-- For tblCropInvertDetail:
SELECT
    COLUMN_NAME,
    DATA_TYPE,
    IS_NULLABLE
FROM INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_NAME = 'tblCropInvertDetail'
AND COLUMN_NAME = 'RATE'

-- For tblCropDirectInvertDetail:
SELECT
    COLUMN_NAME,
    DATA_TYPE,
    IS_NULLABLE
FROM INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_NAME = 'tblCropDirectInvertDetail'
AND COLUMN_NAME = 'RATE'

Expected result:
COLUMN_NAME  DATA_TYPE  IS_NULLABLE
RATE         decimal    YES


2. Check if @RATE parameter exists in SP:
------------------------------------------
SELECT
    PARAMETER_NAME,
    DATA_TYPE
FROM INFORMATION_SCHEMA.PARAMETERS
WHERE SPECIFIC_NAME = 'SP_AddUpdCropInvertDetail'
AND PARAMETER_NAME = '@RATE'

Expected result:
PARAMETER_NAME  DATA_TYPE
@RATE           decimal


3. Check sample data after testing:
------------------------------------
-- Replace 'tblCropInvertDetail' with your actual table name if different
SELECT TOP 5
    CDAID,
    CROPID,
    WEIGHT,
    RATE,      ← Should have values
    PQUNTITY,
    CGRADE,
    (WEIGHT * RATE) AS [Calculated Amount]
FROM tblCropInvertDetail
WHERE ISDELETED = 0
ORDER BY CDAID DESC

Expected: RATE column has values for new records


4. Check master vs detail data:
--------------------------------
-- This shows master total vs sum of details
SELECT
    m.CROPID,
    m.AMOUNT AS [Master Total],
    SUM(d.WEIGHT * d.RATE) AS [Details Total],
    CASE
        WHEN ABS(m.AMOUNT - SUM(d.WEIGHT * d.RATE)) < 0.01 THEN 'Match ✓'
        ELSE 'Mismatch ✗'
    END AS [Status]
FROM tblCropInvertMaster m
INNER JOIN tblCropInvertDetail d ON m.CROPID = d.CROPID
WHERE m.ISDELETED = 0 AND d.ISDELETED = 0
GROUP BY m.CROPID, m.AMOUNT
ORDER BY m.CROPID DESC

Expected: Master Total = Details Total

================================================================================
TROUBLESHOOTING
================================================================================

Issue: "Invalid object name 'tblCropDirectInvertDetail'"
--------------------------------------------------------
Your database uses 'tblCropInvertDetail' instead.
The script auto-detects this - just run it.

Issue: "Column 'RATE' already exists"
-------------------------------------
RATE column already added - no action needed.
The script checks before adding.

Issue: "Invalid column name 'RATE'" when testing
-------------------------------------------------
1. Check if script ran successfully
2. Verify RATE column exists in detail table
3. Restart backend server
4. Clear browser cache

Issue: RATE shows NULL in database
-----------------------------------
For old records: Normal - RATE was added later
For new records after update: Bug - check:
1. Is Rate field filled in UI before clicking "Add Data"?
2. Is backend passing Rate in payload?
3. Is SP receiving @RATE parameter?
